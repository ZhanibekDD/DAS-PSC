# Изолированный закрытый пилот ПСК

Это не production: нет персональных ролей, OCR/ИИ и просмотра оригиналов из реестра.
Рабочие ДАС, Снабжение, ИИ и их конфигурации не меняются.

## Границы

Единственный Compose project `das-psc-pilot`, собственные сеть `das-psc-pilot_psc_only`
и том `das-psc-pilot_psc_data`. Кандидат порта: `127.0.0.1:18090`.
Максимум 1 CPU, 1 ГиБ RAM без swap, 128 процессов, один worker, не более 4 конкурентных
соединений. Tmpfs до 320 МиБ входит в лимит памяти. Логи: 3 файлами по 10 МиБ.
Runtime runc, GPU/devices не подключены, нет общих томов, NAS, Docker socket или host
network. Пользователь 10001, root filesystem read-only, capabilities сняты.

Это обычная отдельная bridge-сеть, НЕ исходящий firewall: технически контейнер может
обращаться к сети/хосту. В приложении не настроены обращения к ДАС/Снабжению/ИИ.
`internal: true` у единственной сети несовместим с публикацией порта на части версий
Docker, поэтому проверяются фактические NetworkSettings.Ports и HTTP, не только
запрошенные PortBindings. Отдельные сети не равны отдельным VM: ядро, диск и сеть хоста
общие. Нулевое влияние не гарантируется; для жесткой изоляции нужен отдельный VM/узел.

Образ строится в CI. На сервере нет docker build, pip install, apt upgrade, рестарта
Docker или изменения общей firewall/nginx-конфигурации. Лимиты контейнера не ограничивают
IO daemon при загрузке образа. Экспорт по image ID без тегов не переназначает чужие теги.
Рост тома SQLite не имеет жесткой дисковой квоты: контролируйте место и число импортов.

## Первый запуск

1. Проверить оба CI workflow нужного commit. В Actions `Isolated pilot package` скачать
   артефакт `psc-isolated-pilot-<SHA>` из проверенного запуска этого репозитория.
   SHA256 защищает от порчи, не заменяет доверие к издателю.
2. Содержимое перенести в НОВЫЙ каталог `$HOME/das-psc-pilot` с правами 0700, не внутрь
   ДАС. Нужны pilot.py, compose.pilot.yml, manifest.json, psc-image.tar.gz и этот документ.
3. Выполнить только чтение состояния:

   ```bash
   python3 pilot.py preflight
   ```

   Нужны Linux x86_64, локальный rootful Docker >=28, Compose v2, действующие cgroup
   limits, >=4 ГиБ доступной RAM, >=2 CPU, умеренная текущая load, >=10 ГиБ и >=10%
   свободного диска. Это консервативные пороги пилота, не бенчмарк. Занятый порт/имена
   проекта/тома/сети дают BLOCKED. Нельзя освобождать их удалением чужих ресурсов,
   остановкой процессов, prune или автоматическим обновлением Docker.
4. После проверки отчета и в разрешенное окно:

   ```bash
   python3 pilot.py start --expect-commit ПОЛНЫЙ_ПРОВЕРЕННЫЙ_SHA
   ```

   При другом выбранном порте добавить `--port НОМЕР` в обе команды. Проверяются
   commit, SHA256 образа и deploy-файлов; Docker загружает образ; preflight повторяется.
   Создаются только собственный контейнер/сеть/том. Image ID immutable, pull/build нет.
   Порт не резервируется между проверкой и запуском: при конфликте ничего не убивается.
   Случайный пароль создается на сервере, логин `psc`. Пароль хранится локально в
   `.state/config.json` (0600, каталог 0700), не печатается в лог. Не присылайте этот файл
   или raw docker inspect / compose config с окружением в чат; не коммитьте .state.
5. PILOT_PASS: проверены реальные лимиты/монтирования/сеть, healthcheck, 401 без пароля
   и 200 с паролем; состояние остальных контейнеров совпало с исходным снимком.
   Это не нагрузочный тест рабочих ДАС/Снабжения/ИИ: отдельно проверить их привычные
   сценарии до/после и наблюдать CPU/RAM/IO. Повторная проверка:

   ```bash
   python3 pilot.py verify
   ```

При неуспешной приемке останавливается только созданный контейнер ПСК, том остается.
При сбое создания сохраняется .state: повторный start отказывается перезаписывать ее.
Скрипт — для первого запуска, не updater и не автоматический откат схемы БД.
Restart policy on-failure:3 ограничивает перезапуски и не поднимает пилот после reboot.
Автозапуск согласовать отдельно после приемки.

## Вход без изменения общего nginx

Для одного оператора — существующий SSH-доступ и шифрованный туннель. Подставить уже
проверенные реквизиты подключения, не угадывать адрес/порт:

```bash
ssh -N -o ExitOnForwardFailure=yes -L 18090:127.0.0.1:18090 -p SSH_PORT SSH_USER@SSH_HOST
```

На рабочем ПК открыть `http://127.0.0.1:18090`, логин `psc`, пароль из локального config.
HTTP только на loopback внутри SSH-туннеля. Не открывать порт на роутере/firewall,
не менять bind на 0.0.0.0. Для команды позже нужны отдельный HTTPS-вход и личные права.

## Остановка и backup

`python3 pilot.py stop` останавливает один контейнер по проверенным project/service
labels, без удаления тома. Нельзя применять down -v, system/volume prune, общую
остановку Docker, изменение конфигов ДАС/Снабжения/ИИ/nginx/SSO.

Перед обновлением фиксировать старый image ID и согласованный backup через
sqlite3.Connection.backup (не копировать один sqlite-файл при активном WAL).
Копию вынести с сервера и проверить в отдельном тестовом каталоге/контейнере.
CI проверяет backup/restore синтетической карточки и сохранение после пересоздания
контейнера. Рабочая backup-политика и внехостовое хранилище еще не настроены.
