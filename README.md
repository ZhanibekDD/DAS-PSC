# DAS-PSC · v0.5 pilot

ПСК — отдельное рабочее пространство: **объект → импорт → реестр → проверка категорий → этапы и предписания**. Рабочий сервер не развертывается автоматически; код до слияния PR находится в `feat/psc-mvp-v0.1`.

## Что работает

Карточки объектов, реестр, версии документов, предпросмотры ZIP/NAS и журнал сохраняются в SQLite. Импорт требует подтверждения; повторный импорт не размножает записи. Есть поиск по кириллице, фильтры, пагинация, SHA-256 дубли и CSV с нейтрализацией формул. Подтвержденные человеком категории не перезаписываются повторным импортом или обновлением машинных правил.

В v0.3 добавлены ручные этапы по участкам, ответственные, даты, один предшественник, проверка зависимостей и блокирующих предписаний. Предписания проходят устранение и проверку перед закрытием. Для закрытия требуется запись подтверждающего документа своего объекта и имя проверившего. Просрочка и счетчики видны в карточке. Полные правила, пределы и тесты: [docs/CONTROL.md](docs/CONTROL.md).

В v0.4 улучшен разбор реестра: точные SHA-256 дубли выводятся группами, правила классификации имеют консервативные уровни high / medium / low, высокоуверенные неизмененные предложения можно подтвердить одной явной операцией, а средние/низкие и неизвестные остаются на ручной проверке. На странице разделов отдельно показано **«найдено по файловым признакам»** и **«подтверждено человеком»**. Наличие файлов в 14 разделах не означает полноту исполнительной документации или процент строительства.

В v0.5 добавлен первый содержательный разбор документов. Для PDF с текстовым слоем и DOCX ПСК читает текст во временной памяти, извлекает только производные признаки и сопоставляет их с именем/путем. Исходный текст документа в SQLite не сохраняется. Если сильные признаки имени/пути и содержания конфликтуют, документ переводится на ручную проверку, а не подтверждается автоматически. PDF без извлекаемого текстового слоя помечается **«нужен OCR»** — само OCR в v0.5 еще не выполняется.

Для уже существующего реестра можно повторно загрузить **тот же ZIP**. Совпадение выполняется по точному пути и SHA-256. Перед применением ПСК показывает отдельный предпросмотр: сколько производных результатов анализа будет записано, сколько машинных предложений изменится и сколько подтвержденных человеком записей защищено. Применение требует явного подтверждения и state-token; устаревший предпросмотр отклоняется.

### Границы содержательного анализа v0.5

- Поддерживаются текстовый слой PDF и текст DOCX; DWG/DXF/XLS/XLSX и изображения пока классифицируются по имени/пути.
- Один файл для содержательного чтения ограничен 32 МиБ; PDF анализируется максимум по первым 40 страницам, а экстремально большие PDF пропускаются.
- DOCX читается как ограниченный набор XML-разделов с защитой XML-парсинга.
- В базе хранятся статус анализа, число извлеченных символов/страниц, производная классификация и digest результата — **не исходный текст**.
- Оценка уверенности — сила правил, не калиброванная вероятность правильности и не экспертное заключение.
- OCR, полноценная семантическая модель/LLM, защищенный просмотр оригиналов, пользовательские роли/SSO, Android/offline и внешние интеграции пока не входят в v0.5.

## Локальный запуск

Python 3.11 или 3.12:

```bash
git clone --branch feat/psc-mvp-v0.1 https://github.com/ZhanibekDD/DAS-PSC.git
cd DAS-PSC
python -m venv .venv
source .venv/bin/activate  # PowerShell: .venv\Scripts\Activate.ps1
pip install -e '.[dev]'
uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. Создайте объект → загрузите ZIP → изучите предпросмотр → подтвердите реестр → проверьте категории. Для реестра, созданного старой версией, повторная загрузка того же ZIP выполнит новый анализ, но не применит его к подтвержденному реестру без отдельного явного подтверждения.

Без `PSC_PASSWORD` разрешено только локальное соединение. Общий логин пилота — `psc`, пароль задает оператор (минимум 9 символов). Для сетевого адреса нужны `PSC_ALLOWED_HOSTS`, пароль и отдельный HTTPS reverse proxy. **Не публикуйте пилот в интернете: пользовательских ролей пока нет.** Имя проверившего вводится вручную и не является установленной личностью или электронной подписью.

## Docker

Скопируйте `.env.example` в `.env`, задайте свой пароль:

```bash
docker compose up --build -d
docker compose logs --tail=100 psc
```

Порт привязан к `127.0.0.1:8080`; контейнер без root, корневая файловая система read-only. База находится в отдельном томе `psc-data`. **`docker compose down -v` удалит данные.** Действующие ДАС/Снабжение не подключаются и не меняются.

Часовой пояс сроков: `PSC_TIMEZONE=UTC` по умолчанию; для нужного пояса задайте IANA-имя, например `Asia/Yekaterinburg`. На Windows для других поясов может потребоваться `pip install tzdata`. Compose читает `.env`; при запуске uvicorn экспортируйте переменные или добавьте `--env-file .env`.

## Источники и NAS

`PSC_DATA_DIR` (по умолчанию `./data`) хранит метаданные, производные результаты анализа, историю и контроль работ. **Оригиналы документов и извлеченный исходный текст приложением постоянно не хранятся.** ZIP храните отдельно в защищенном хранилище. Временная загрузка закрывается после анализа.

NAS dry-run только для Linux/Unix, через операторскую CLI и read-only mount:

```bash
python -m app.cli /mnt/approved-readonly-nas --relative project-folder
python -m app.cli /mnt/approved-readonly-nas --relative project-folder --project PROJECT_ID
```

NAS dry-run в v0.5 остается анализом метаданных/имени/пути и SHA-256; содержательный разбор исходников через NAS веб-интерфейс не добавлялся. Сканер не перемещает, не переименовывает и не удаляет исходники. Небезопасные ссылки пропускаются с предупреждениями; произвольных серверных путей в веб-API нет. ZIP ограничен 256 МиБ, суммарное содержимое 1 ГиБ, 5000 элементов и обязательный проход хеширования ограничен по времени; содержательный разбор выполняется отдельным best-effort проходом с собственным бюджетом времени. Публичный доступ запрещен.

Не коммитьте рабочие файлы, БД, пароли, NAS-пути и отчеты с реальными именами документов даже в приватный Git. Тесты/CI используют только синтетические данные. Видимость репозитория не заменяет защиту приложения.

## Обновление и проверки

Перед обновлением сделайте согласованную копию SQLite через `sqlite3.Connection.backup`, не копируйте только основной файл при активном WAL. v0.5 добавляет отдельную таблицу производных результатов анализа без удаления или перезаписи существующего реестра. Старые подтвержденные пользователем записи должны оставаться защищенными.

```bash
pytest -q
pip wheel --no-deps .
# Дополнительный браузерный сценарий (нужен Playwright и Chromium):
python scripts/browser_smoke.py
```

CI проверяет Python 3.11/3.12, установленный пакет вне checkout, Docker и отдельный Chromium browser smoke. Изолированный pilot workflow отдельно проверяет запуск, backup/restore, пересоздание только контейнера ПСК и сохранность внешнего sentinel. Смотрите итог именно текущего коммита.

Оценка готовности и ее основания: [docs/READINESS.md](docs/READINESS.md). Описание реестра v0.2: [docs/MVP_SCOPE.md](docs/MVP_SCOPE.md); новые возможности v0.3–v0.5 уточняют указанные там ограничения. Правила разработки: [AGENTS.md](AGENTS.md).
