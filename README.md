# DAS-PSC · v0.2 pilot

ПСК — отдельное рабочее пространство строительного объекта: **паспорт → анализ ZIP → подтверждение импорта → реестр → проверка категорий**.

## Реализовано

- Постоянное хранение объектов, импортов, реестра и журнала изменений в SQLite.
- Создание и редактирование паспорта: заказчик, подрядчик, ответственный, даты, ручной этап и процент работ. Никаких предзаполненных «42%» и вымышленных рабочих объектов.
- Предпросмотр ZIP и явное подтверждение сохранения реестра. До подтверждения документы не попадают в основной реестр.
- Повторный импорт идемпотентен. Одинаковый путь с другим SHA-256 сохраняется отдельной версией; одинаковое содержимое по разным путям сохраняется для проверки, а не удаляется.
- Поиск, фильтры категорий, непроверенных записей, точных дублей, пагинация и CSV-экспорт с нейтрализацией формул.
- Исправление и подтверждение категории человеком, защита от перезаписи устаревшей карточки, журнал действий.
- NAS dry-run через операторскую CLI: только чтение локально смонтированного разрешенного корня, без симлинков. Веб-доступа к произвольным путям сервера нет.
- Проверки ZIP: пути, символические ссылки, шифрование, повторные имена, CRC, лимиты размера, числа элементов, степени сжатия и времени.
- Локальный доступ по умолчанию, пароль для контейнерного пилота, защита межсайтовых записей, ограничение тела запроса. Docker работает без root; данные находятся в отдельном томе.

**Важно:** классификация работает по правилам имени/пути, а не через ИИ или OCR. Код и ревизия — предположения. Подтверждение категории не означает проверку содержания документа.

## Что означает «Наличие разделов»

14 верхнеуровневых разделов взяты из предоставленного шаблона папки. Названия сохранены, в том числе исходное «Ход строильства объекта». Пустые `.txt` в шаблоне — обозначения разделов; вложенное «ТУ на пересечение» относится к ППР и ТК.

Показатель считает разделы, в которых найдены непустые неслужебные файлы. Это **не процент полноты исполнительной документации, не подтверждение обязательности каждого раздела и не готовность строительства**. «Не найдено» означает только «нет в загруженном реестре». Процент работ вводится отдельно вручную. Настоящий чек-лист необходимых актов и требования для каждого объекта еще должны быть согласованы.

## Быстрый локальный запуск

Нужен Python 3.11 или 3.12. До слияния PR код находится в `feat/psc-mvp-v0.1`, а не в `main`.

```bash
git clone --branch feat/psc-mvp-v0.1 https://github.com/ZhanibekDD/DAS-PSC.git
cd DAS-PSC
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -e '.[dev]'
uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. При первом запуске объектов нет. Создайте карточку, загрузите ZIP, проверьте предложения и нажмите «Подтвердить и сохранить реестр».

Без `PSC_PASSWORD` допускается только локальное соединение. Для сетевого адреса задайте надежный пароль (минимум 12 символов), `PSC_ALLOWED_HOSTS` и HTTPS на отдельном reverse proxy. Логин общего пилотного аккаунта — `psc`. Роли и разграничение по пользователям **пока отсутствуют**. Не публикуйте пилот в интернете.

## Docker

Создайте `.env` из `.env.example`, задайте собственный случайный `PSC_PASSWORD`. Compose сам читает `.env`. Для обычного запуска через uvicorn переменные нужно экспортировать или указать `--env-file .env`.

```bash
docker compose up --build -d
docker compose logs --tail=100 psc
```

Порт привязан к `127.0.0.1:8080`; серверные адреса и рабочие NAS-учетные данные не зашиты в код. База хранится в именованном томе `psc-data`, переживает перезапуск и пересоздание контейнера. **`docker compose down -v` удалит том.** Действующие ДАС/Снабжение и их контейнеры не подключаются и не изменяются.

## NAS dry-run (Linux/Unix)

```bash
python -m app.cli /mnt/approved-readonly-nas --relative project-folder
# Сохранить предпросмотр в уже созданный объект, затем подтвердить его в браузере:
python -m app.cli /mnt/approved-readonly-nas --relative project-folder --project PROJECT_ID
```

Используйте read-only mount и отдельного пользователя с минимальными правами. `--relative` не выходит за выбранный корень; ссылки и специальные файлы пропускаются с предупреждениями. Пропущенные элементы видны в предпросмотре. Для Windows используйте ZIP. Сканер не копирует, не переименовывает и не удаляет исходники.

## Где находятся данные

`PSC_DATA_DIR` (по умолчанию `./data`) содержит БД с метаданными, предпросмотрами и журналом. Сами документы **не сохраняются приложением постоянно**: загрузка может использовать временный файл, который закрывается после обработки. Реальный ZIP нужно сохранить в защищенном хранилище отдельно. Скачивание/просмотр PDF/DWG из реестра еще не реализованы.

Даже метаданные и пути могут быть конфиденциальны. Не коммитьте БД, реальные ZIP/PDF/DWG/фото, NAS-пути, пароли, отчеты с именами документов или рабочие фикстуры, независимо от видимости репозитория. Приватность GitHub не заменяет защиту запущенного приложения. В тестах — только синтетические данные.

Для согласованной копии живой SQLite используйте API `sqlite3.Connection.backup`, а не копирование только основного файла при активном WAL. Не удаляйте БД для обновления схемы. Текущая версия схемы — 1.
