# DAS-PSC · v0.4 pilot

ПСК — отдельное рабочее пространство: **объект → импорт → реестр → проверка категорий → этапы и предписания**. Рабочий сервер не развертывается автоматически; код до слияния PR находится в `feat/psc-mvp-v0.1`.

## Что работает

Карточки объектов, реестр, версии документов, предпросмотры ZIP/NAS и журнал сохраняются в SQLite. Импорт требует подтверждения; повторный импорт не размножает записи. Есть поиск по кириллице, фильтры, пагинация, SHA-256 дубли и CSV с нейтрализацией формул. Подтвержденные человеком категории не перезаписываются повторным импортом.

В v0.3 добавлены ручные этапы по участкам, ответственные, даты, один предшественник, проверка зависимостей и блокирующих предписаний. Предписания проходят устранение и проверку перед закрытием. Для закрытия требуется запись подтверждающего документа своего объекта и имя проверившего. Просрочка и счетчики видны в карточке. Полные правила, пределы и тесты: [docs/CONTROL.md](docs/CONTROL.md).

В v0.4 улучшен разбор реального реестра: точные SHA-256 дубли выводятся отдельными группами, правило классификации получает уровень уверенности, высокоуверенные неизмененные предложения можно подтвердить одной явной массовой операцией, а средние/низкие и неизвестные остаются на ручной проверке. На странице разделов отдельно показано **«найдено по файловым признакам»** и **«подтверждено человеком»**, чтобы 4/14 не выглядело как готовность объекта. Массовая операция имеет отдельное подтверждение и не удаляет файлы.

Классификация — правила имени/пути, **не ИИ/OCR**. Оценка уверенности — сила правил, а не вероятность правильности. Код и ревизия являются предположениями. Наличие файлов в 14 разделах исходного шаблона **не означает полноту исполнительной документации**. Общий процент строительства вводится вручную; по числу папок или завершенных этапов он не вычисляется. Нет вымышленных процентов и демо-записей в рабочей БД.

## Локальный запуск

Python 3.11 или 3.12:

```bash
git clone --branch feat/psc-mvp-v0.1 https://github.com/ZhanibekDD/DAS-PSC.git
cd DAS-PSC
python -m venv .venv
source .venv/bin/activate  # PowerShell: .venv\Scripts\Activate.ps1
pip install -e '.[dev]'
uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. Создайте объект → загрузите ZIP → подтвердите реестр → проверьте категории. Высокоуверенные предложения можно подтвердить отдельной массовой кнопкой после просмотра. Затем откройте «Ход работ и предписания». ID документа отображается в реестре рядом с названием.

Без `PSC_PASSWORD` разрешено только локальное соединение. Общий логин пилота — `psc`, пароль задает оператор (минимум 9 символов). Для сетевого адреса нужны `PSC_ALLOWED_HOSTS`, пароль и отдельный HTTPS reverse proxy. **Не публикуйте пилот в интернете: пользовательских ролей пока нет.** Имя проверившего вводится вручную и не является установленной личностью или электронной подписью.

## Docker

Скопируйте `.env.example` в `.env`, задайте свой пароль:

```bash
docker compose up --build -d
docker compose logs --tail=100 psc
```

Порт привязан к `127.0.0.1:8080`; контейнер без root, корневая файловая система read-only. База находится в отдельном томе `psc-data`. **`docker compose down -v` удалит данные.** Действующие ДАС/Снабжение не подключаются и не меняются.

Часовой пояс сроков: `PSC_TIMEZONE=UTC` по умолчанию; для нужного пояса задайте IANA-имя, например `Asia/Yekaterinburg`. На Windows для других поясов может потребоваться `pip install tzdata`. Compose читает `.env`; при запуске uvicorn экспортируйте переменные или добавьте `--env-file .env`.

## Источники и NAS

`PSC_DATA_DIR` (по умолчанию `./data`) хранит метаданные, предпросмотры, историю и контроль работ. **Оригиналы документов не хранятся приложением постоянно, просмотр PDF/DWG еще не реализован.** ZIP храните отдельно в защищенном хранилище. Временная загрузка закрывается после анализа.

NAS dry-run только для Linux/Unix, через операторскую CLI и read-only mount:

```bash
python -m app.cli /mnt/approved-readonly-nas --relative project-folder
python -m app.cli /mnt/approved-readonly-nas --relative project-folder --project PROJECT_ID
```

Сканер не перемещает, не переименовывает и не удаляет исходники. Небезопасные ссылки пропускаются с предупреждениями; произвольных серверных путей в веб-API нет. ZIP ограничен 256 МиБ, суммарное содержимое 1 ГиБ, 5000 элементов, 60 секунд анализа. Параллельные тяжелые загрузки нужно ограничивать на reverse proxy. Публичный доступ запрещен.

Не коммитьте рабочие файлы, БД, пароли, NAS-пути и отчеты с реальными именами документов даже в приватный Git. Тесты/CI используют только синтетические данные. Видимость репозитория не заменяет защиту приложения.

## Обновление и проверки

Перед обновлением сделайте согласованную копию SQLite через `sqlite3.Connection.backup`, не копируйте только основной файл при активном WAL. Не удаляйте старую БД: модуль добавляет свои таблицы транзакционно, сохраняя реестр. Версия реестра 1; версия модуля контроля 1. Полноценная эксплуатационная проверка backup/restore еще требуется.

```bash
pytest -q
pip wheel --no-deps .
# Дополнительный браузерный сценарий (нужен Playwright и Chromium):
python scripts/browser_smoke.py
```

CI: Python 3.11/3.12, установленный пакет вне checkout, Docker и сохранение этапа/предписания после рестарта, отдельный браузерный сценарий desktop/mobile. Смотрите итог именно текущего коммита. Полная концепция не завершена: нет защищенного просмотра оригиналов, содержательного чек-листа ПТО, OCR/ИИ, ролей/SSO, офлайн-приложения и внешних интеграций.

Оценка готовности и ее основания: [docs/READINESS.md](docs/READINESS.md). Описание реестра v0.2: [docs/MVP_SCOPE.md](docs/MVP_SCOPE.md); новые возможности v0.3/v0.4 уточняют указанные там ограничения. Правила разработки: [AGENTS.md](AGENTS.md).
