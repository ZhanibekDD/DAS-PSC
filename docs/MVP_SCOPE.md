# ПСК v0.2 — границы пилота

## Приемочный сценарий

1. Создать пустой объект: без демо-документов и автоматических процентов.
2. Загрузить синтетический или локальный рабочий ZIP. Увидеть пути, размеры, SHA-256 и предложения категорий.
3. До подтверждения основной реестр остается прежним. После подтверждения появляются все записи.
4. Открыть реестр: поиск по кириллице, фильтры, 100 записей на страницу, экспорт CSV.
5. Исправить категорию, увидеть журнал. Устаревшая версия формы должна вернуть конфликт, а не стереть чужую правку.
6. Повторить импорт: 0 новых записей. Изменить содержимое по прежнему пути: сохранить отдельную версию.
7. Пересоздать приложение/контейнер с прежним томом: карточка и реестр остаются.
8. Проверить, что исходный ZIP и файлы NAS не изменились.

## Модель данных

Projects: паспорт, даты, ручной этап/процент, версия записи.
Imports: серверный манифест, digest, pending/confirmed/cancelled.
Documents: исходный путь, SHA-256, размер, предположения кода/ревизии, предложенная и выбранная категории, флаг проверки категории.
Import_documents: происхождение записей из импортов.
Events: журнал действий пилотного общего аккаунта. Это не защищенный от администратора журнал подписей.

Подтверждение импорта — одна транзакция SQLite BEGIN IMMEDIATE. Уникальность документа задается (объект, путь, SHA-256). Нет глобального дедуплицирования между заказчиками. Предполагаемое размещение — категория в БД, не физическое действие над хранилищем.

## Ограничения

- Правила классификации, не ИИ. Их score не является калиброванной вероятностью.
- Нет чтения содержания PDF, числа страниц, OCR, проверки подлинности/подписей, просмотра и скачивания оригиналов.
- Нет пользовательских ролей, SSO, пообъектных разрешений или юридически значимого подписания. Общий аккаунт psc — только для закрытого пилота.
- Нет автоматического прогресса по объемам, зависимостей строительных процессов, автоматического закрытия предписаний или исполнительной документации.
- NAS — локально смонтированная папка и операторская CLI. Нет подключения сетевых учетных записей из браузера.
- Анализ синхронный с ограничениями (256 МиБ загрузка/файл, 1 ГиБ суммарно, 5000 элементов, 60 секунд). Очередь фоновых задач и квоты хранения предпросмотров — следующий этап. Параллельные тяжелые загрузки требуют ограничения на reverse proxy; публичный доступ запрещен.
- Определенные категории и ранее сохраненные версии участвуют в индикаторе наличия разделов. Он не определяет действующую ревизию, обязательность или полноценность комплекта.

## Следующая полезная итерация

Защищенное read-only хранилище оригиналов, просмотр PDF и ссылка из каждой записи к исходному документу. Затем — согласованный с ПТО чек-лист конкретных необходимых документов вместо процента заполнения папок. Только после этого подключать извлечение содержания и ИИ с источниками для каждого поля.

## Техническая основа

Использованы FastAPI/Starlette, стандартные sqlite3/zipfile. Документация:
- https://fastapi.tiangolo.com/advanced/templates/
- https://docs.python.org/3/library/zipfile.html#decompression-pitfalls
- https://docs.python.org/3.11/library/sqlite3.html#transaction-control

Проверки в tests/ используют только синтетические материалы. Результаты прогонов на рабочих архивах и их манифесты в Git не сохраняются.
