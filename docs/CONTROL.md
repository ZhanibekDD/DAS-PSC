# ПСК v0.3 — ход работ и предписания

## Реализованный сценарий

Карточка объекта → Ход работ и предписания → добавить этап по участку → назначить ответственного и даты → указать зависимость → зарегистрировать замечание → устранить → отправить на проверку → закрыть с подтверждающим документом.

Этап содержит вид работ, участок/пикеты (свободный текст), ответственного, плановые даты, статус, вручную введенный процент, один предшествующий этап, ID связанного документа и примечание. Типовая технологическая последовательность не создается автоматически. При явном выборе статуса «Завершен» форма устанавливает 100%; это ввод пользователя, не расчет по актам или объемам. Общий процент в паспорте не усредняется по этапам.

## Правила контроля

- Для статусов «В работе»/«Завершен» предшественник должен быть завершен. Циклы и зависимости на чужой объект запрещены. Чтобы повторно открыть предшественника, сначала переведите зависимые активные/завершенные этапы в блокировку.
- Незакрытое блокирующее предписание препятствует отметке запуска/завершения связанного этапа. Без привязки к этапу оно действует на весь объект. Этот признак выбирает человек; не каждое предписание автоматически блокирующее.
- Новое замечание можно зарегистрировать после завершения этапа. ПСК не переписывает факт в прошлом, а показывает противоречие и необходимость проверки.
- Предписание: открыто / устраняется / на проверке / закрыто. Описание устранения обязательно для последних двух состояний. Закрытие возможно только после «На проверке»; требуется имя проверившего и непустой неслужебный документ своего объекта с подтвержденной категорией. Это не проверка содержания или подлинности документа.
- Для изменения закрытого предписания сначала откройте его повторно. Снимки до/после сохраняются в control_changes, краткое событие — в существующем журнале объекта. Старое закрытие остается в истории.
- Просрочка: срок раньше текущей даты, статус не закрыт. День срока не считается просроченным. По умолчанию UTC; PSC_TIMEZONE задает IANA-часовой пояс, например Asia/Yekaterinburg. Использованный пояс показан на экране. Отправки email/MAX-напоминаний пока нет.
- 200 этапов и 2000 предписаний на объект в пилоте. Предписания выводятся по 50 на страницу; фильтры по статусу и просрочке.

## Данные и безопасность

Модуль добавляет work_stages, prescriptions, control_changes, control_meta и индексы, не удаляя прежние таблицы и документы. Инициализация выполняется в транзакции. Версия модуля хранится отдельно (control_meta=1); схема реестра остается user_version=1. Не открывайте новую базу старыми сборками в рабочей эксплуатации. Сделайте резервную копию перед обновлением.

Связи документов/этапов ограничены объектом на уровне API и составных внешних ключей SQLite. Изменения защищены номером версии от перезаписи устаревшей формой. Используются прежние аутентификация и защита запросов. Общий аккаунт пилота не обеспечивает разделение ролей; «проверивший» вводится вручную, не является установленной личностью, подписью или независимым подтверждением.

Это организационный контроль записей, а не допуск к работам, инженерная экспертиза или автоматическая проверка требований безопасности. Источники не изменяются, оригиналы не сохраняются этим модулем.

## Проверка

`pytest -q` — синтетические API/БД тесты, миграция, зависимости, блокировки, просрочка, версии, межобъектная изоляция и история.

`python scripts/browser_smoke.py` — настоящий Chromium + локальный HTTP-сервер: создание объекта, импорт ZIP, подтверждение категории, этап, предписание, устранение, закрытие, перезагрузка. Два размера экрана: 1440×1000 и 390×844. Нужен Playwright 1.57.0 и установленный Chromium. В CI выделено отдельное задание. Локальная среда разработки блокирует браузерный HTTP-запрос политикой; локально этот тест не объявляется пройденным. Итог CI проверяется по конкретному коммиту.

Следующий приоритет: безопасный просмотр оригиналов и согласованный с ПТО чек-лист конкретных документов. Далее — резервное копирование/восстановление и приемка отдельного развертывания. ИИ, OCR, полноценные роли, офлайн-приложение и внешние интеграции остаются отдельными задачами.
